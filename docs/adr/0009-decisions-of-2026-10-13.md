## What is stored, and what a link does

From [state-storage-and-url.md](../research/state-storage-and-url.md).

1. **The map: the URL always wins.**
2. **General rule:** the value in the URL, else the person's stored choice, else the default. A link
   never writes to storage.
3. **After a link:** no banner. While the person touches nothing, the link's value holds for the
   visit only. The first change the person makes is their own choice and is stored like any other
   change. The control shows a small mark when the view differs from the stored choice, with a way
   back to the stored choice.
4. **Last map position:** stored while the person moves the map, used only when the URL names no
   position. A link's position is not stored; the next move by the person is.
5. **iD's link parameters** (background, overlays, photo layer, data, changeset comment): Maid acts
   on them for the visit and stores nothing.

State: open. This replaces the banner built in d4b302d and de586f4.

## Translations

From the two studies.

1. Languages: English, German, French, Spanish. Written in the repo by the team and by agents. No
   community platform.
2. Maid's own texts (about 500): **Paraglide JS** in one shared package, the message files committed,
   the compiled output generated by a script before dev, check and test. Pinned to the version the
   traffic sign tool uses.
3. Preset texts (about 6,000 per language): read from the pinned tagging schema package by a
   transform script into one JSON file per language; only the active language is loaded. Gaps fall
   back to English; corrections live in the repo as overrides.
4. Language choice: URL parameter, then the stored choice, then the browser's language, then English.
   Switching reloads the page. Tests and checks run in English.
5. Headless packages (validation, operations, undo labels) return a message id with values, not a
   sentence; the text is made where it is shown. The journal stores the id and values.
6. Two steps: first the package, the language choice, the preset texts and the UI; then validation,
   operations and undo labels.
7. Tools: only the repo's own script that lists missing keys per language as JSON and fails the
   check when a key lacks a language. No machine translation service, no editor extension.
8. French and Spanish go live as drafts written by agents, marked unreviewed in the repo until a
   person has read them.

State: open.

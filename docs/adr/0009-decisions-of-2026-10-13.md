## What is stored, and what a link does

From [state-storage-and-url.md](../research/state-storage-and-url.md).

1. **The map: the URL always wins.**
2. **General rule:** the value in the URL, else the person's stored choice, else the default. A link
   never writes to storage.
3. **After a link:** no banner. While the person touches nothing, the link's value holds for the
   visit only. The first change the person makes is their own choice and is stored like any other
   change. The control shows a small mark when the view differs from the stored choice, with a way
   back to the stored choice.
4. **Last map position:** stored while the person moves the map, used only when the URL names no
   position. A link's position is not stored; the next move by the person is.
5. **iD's link parameters** (background, overlays, photo layer, data, changeset comment): Maid acts
   on them for the visit and stores nothing.

State: open. This replaces the banner built in d4b302d and de586f4.

## Translations

From the two studies.

1. Languages: English, German, French, Spanish. Written in the repo by the team and by agents. No
   community platform.
2. Maid's own texts (about 500): **Paraglide JS** in one shared package, the message files committed,
   the compiled output generated by a script before dev, check and test. Pinned to the version the
   traffic sign tool uses.
3. Preset texts (about 6,000 per language): read from the pinned tagging schema package by a
   transform script into one JSON file per language; only the active language is loaded. Gaps fall
   back to English; corrections live in the repo as overrides.
4. Language choice: URL parameter, then the stored choice, then the browser's language, then English.
   Switching reloads the page. Tests and checks run in English.
5. Headless packages (validation, operations, undo labels) return a message id with values, not a
   sentence; the text is made where it is shown. The journal stores the id and values.
6. Two steps: first the package, the language choice, the preset texts and the UI; then validation,
   operations and undo labels.
7. Tools: only the repo's own script that lists missing keys per language as JSON and fails the
   check when a key lacks a language. No machine translation service, no editor extension.
8. French and Spanish go live as drafts written by agents, marked unreviewed in the repo until a
   person has read them.

State: open.

## Later the same day

Zoom and loading ([zoom-study.md](../research/zoom-study.md), [fetching-audit.md](../research/fetching-audit.md)):

- Editing below the load zoom (16) is allowed, as in Rapid. First an operation refuses a feature that is less than 80 % in view ("too large", as iD and Rapid).
- Below the load zoom the selection is always drawn; the rest of what is loaded is drawn down to zoom 12 and hidden below. A switch shows only the selection.
- The camera stops at the world view, as in iD and Rapid.
- Notes load from zoom 14. When the API's limit cut the list, a toast says so.
- Failed requests: at most two retries with a growing pause, never on a 4xx answer. "Too many requests" (429, 509) pauses the whole service for the time it names, else 10 seconds, doubling to 60, with a notice. Wikimedia one request at a time, the others six. Map data tiles get a time limit of 30 seconds and are cancelled when they leave the view.
- The wiki's answers are kept 30 days across visits; within a session a thing is asked once.
- The street-level photo layer loads nothing until a person switches it on (Mapillary allows 50,000 tile requests a day for the whole token).
- Suggestions for keys and values come from taginfo as in iD, when a person types, under the rules above; off in automated runs.

Fields and presets:

- The address field takes its format from the country the feature lies in, with `@rapideditor/country-coder` (offline). The same package makes presets, fields and defaults that are bound to countries apply only there.
- Several features selected and one is read-only: the whole change is refused, with the reason.
- Overlapping features: when the context menu closes, the stack ends with it.
- The tags sheet: see the decisions at the end of [sheet-design.md](../research/sheet-design.md).

The apps:

- Two apps in this monorepo that start on their own: `apps/maid` (the default editor, port 5173) and `apps/maid-bicycle` (the bicycle editor that takes over the Radnetz fork's features, port 5176). The shell moves from `apps/maid` into a package so that an app is a config and its own modules. `bun run dev` starts both.
- The Radnetz proposals, confirmed for `apps/maid-bicycle`: the TILDA bike infrastructure section with its checklist and rule; the operations "extract a side into its own way" and "merge a cycleway and a footway"; age colours and a way's images for the photo layer; infra3D links; the traffic sign field as a Maid field on `@osm-traffic-signs/converter`.
- Surface and smoothness by photo is switched on in the default editor now. Its data package is GPL-3.0-or-later; the licence question is settled later (Tobias).

How someone makes their own editor (this replaces "a fork depends on the published npm packages" in [02-fork-model.md](../architecture/02-fork-model.md) as the first way; publishing packages stays possible later):

- A new editor forks this repository and adds its app inside the fork (`apps/maid-golf`), with its own modules in `packages/` and, where needed, changes to the core.
- A GitHub variable in the fork names the app directory that is built and deployed to GitHub Pages.
- Changes go back as pull requests; the fork takes over upstream by merging. Work that stays in the fork's own app and module directories merges without conflicts; a change to the core is a small commit of its own, meant for a pull request.
- Reason given: this is the best setup for development with coding agents, which see the whole code and need no release in between.
- The README's opening explains the name only as the abbreviation of "MapLibre iD".

Turning and tilting the map ([rotate-and-tilt.md](../research/rotate-and-tilt.md)):

- Turning first, tilting after. Until tilting is built it is switched off entirely (keys and touch too).
- Tilting, when it comes, up to 45 degrees.
- The mouse turns the map as in Rapid: a drag with Alt or Control held, started on open map. The right click stays the context menu.
- A compass button appears while the map is turned (or tilted) and resets it; key N.
- Labels, pins and icons stay upright.
- `map=` carries the turn and the tilt as a fourth and fifth part when they are not zero, in tilda-geo's order (zoom, latitude, longitude, bearing, pitch); the stored last position keeps them too. A link with three parts works as before.
- Shift with the arrow keys turns in small steps (2.5 degrees, as Rapid).

Language and small things:

- In the chat and in the app's German texts the informal "Du".
- After an upload the toast is the only success message; the save flyout closes.
- The search fields of the type picker and of "Add field" get a magnifier icon.
- The restore dialog shows the steps and the changed features directly, without disclosures; "Show on the map" is removed.

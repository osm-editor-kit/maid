# What Maid has built

The index of Maid's features, editors and packages. Generated by `bun run features-doc` from
`tools/deploy/showcase/features.ts`, `apps/<app>/overview.json` and the app configs; edit those, not this file. The
same data makes the overview page of the deployed site (https://osm-editor-kit.github.io/maid/).

## Features compared with iD and Rapid

✓ yes, ◐ partly, – no; ✦ all have it, Maid does it differently. iD is [openstreetmap/iD](https://github.com/openstreetmap/iD), Rapid is
[bhousel/Rapid](https://github.com/bhousel/Rapid), both checked in their code on their main branches (2026-11-12). A Maid
column follows the modules the app's config calls.

## Packages

Every package in `packages/`, with the first paragraph of its README. Modules (`module-*`) are switched on per app,
with the apps that call them; the other packages are shared by the apps and modules that import them.

| Package | What it is | Apps |
| --- | --- | --- |
| [core](../packages/core/README.md) | The headless core of Maid. It has no DOM, no React and no MapLibre. React bindings are a separate entry, `@osm-editor-kit/maid-core/react` (`useExtensionPoint`). It owns the editor's data: `editor.context` and `editor.history` from `maid-model` (graph, edits, undo and redo). It has only the mechanism that modules plug into. No dependencies. | shared |
| [filters](../packages/filters/README.md) | Which features an editor lets you edit, only look at, or not see at all. Headless and without dependencies. The design is in [docs/architecture/06-filters.md](../../docs/architecture/06-filters.md). | shared |
| [i18n](../packages/i18n/README.md) | Maid's own texts (not the preset texts, which come later) in English, German, French and Spanish, with Paraglide JS 2.25.4. The decisions are in [ADR 0009](../../docs/adr/0009-decisions-of-2026-10-13.md), section Translations. | shared |
| [journal](../packages/journal/README.md) | The journal keeps the unsaved edits of an editor in the browser, so that they survive a reload. It is headless: no React, no DOM beyond IndexedDB and the Web Locks API. It reads an `EditHistory` from `@osm-editor-kit/maid-model` and writes to IndexedDB through Dexie. It never changes the history. | shared |
| [levels](../packages/levels/README.md) | Reads the building levels of OSM features: `level`, `repeat_on`, `min_level` and `max_level`, with the problems in them, and the floors a set of features is on. It has no map and no editor, so the level mode (`packages/module-levels`), the renderer and the level rules of the validation can all use it. | shared |
| [maproulette](../packages/maproulette/README.md) | The MapRoulette logic of Maid as pure TypeScript: no UI, no React, no DOM, no globals (no `window`, no `sessionStorage`). Every request goes through a `fetch` function that the caller injects, and the way a request signs in (`MapRouletteAuth`) is injected too, so the package can be tested with a fake `fetch` and never talks to maproulette.org by itself. | shared |
| [model](../packages/model/README.md) | The data model of Maid: OSM entities, the graph, differences, geometry, the edit actions, and (in progress) undo history, the spatial index and the tagging-schema lookup. | shared |
| [module-bike-infrastructure](../packages/module-bike-infrastructure/README.md) | The default look of the bicycle editor: the bicycle infrastructure as [TILDA](https://tilda-geo.de) classifies it, drawn over iD's style. Every highway goes through TILDA's processing (`processBikelanes` of `@tilda-geo/bicycle-infrastructure`), which splits it into the way itself and its road sides and gives each part a category. | maid-bicycle |
| [module-buildings](../packages/module-buildings/README.md) | The building editor of Maid Buildings (`apps/maid-buildings`): an editor for building mapping campaigns. Its map style follows the building styles of Pierre-Léo Bourbonnais's iD fork, [kaligrafy/iD](https://github.com/kaligrafy/iD) (branch `v5`, `css/50_misc.css` and `modules/svg/tag_classes.js`; branch `feat/quebec-building-styles`, `lenses/v5-quebec.css`; branch `feat/building-levels-always-visible`), read on 2026-11-13. No code of the fork is copied: its colours and rules are written here as a Maid lens. | maid-buildings |
| [module-climbing](../packages/module-climbing/README.md) | The climbing section of Maid Climbing (`apps/maid-climbing`): crags, boulders and their routes. Plan and research: [docs/research/climbing.md](../../docs/research/climbing.md). | maid-climbing |
| [module-data-layers](../packages/module-data-layers/README.md) | Other data drawn under the OSM data: GeoJSON, GPX, PMTiles and vector tiles. A "Data layers" flyout in the top bar lists the layers, switches them on and off, and adds new ones.
